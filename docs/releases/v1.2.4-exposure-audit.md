# v1.2.4 发布产物暴露面审计

## 1. 总览

对象是本项目 Windows x64 自包含目录。项目按 MIT 开源，C# 可反编译是预期的发布形态，不将其误报为源码泄密。审计使用已安装的 `reverse-engineering-exposure-audit` 静态扫描器，未执行受检程序。

初始工具评分为 52 / 100、等级 D，包含 .NET 运行时及第三方程序集；该启发式评分不能等同于本项目的安全评级。原始结果位于本地 `.evolution/verification/exposure-baseline.json`，发布配置复测位于 `exposure-1.2.4.json`。本地发布构建、113 项安全回归和 WPF 扫描页面验证通过；真实杀毒、安装、更新端到端不由此证明。

复测工具评分仍为 52 / 100、等级 D：托管程序集 297 项、CodeView 路径 313 项（原 314 项）、无签名目录 34 项。磁盘上的 4 个本项目 PDB 已不再分发；程序集中的 CodeView 元数据不等同于外置 PDB，不能宣称全部调试路径已消失。第三方路径和授权字段两类命中未变化，已人工分类如下。

## 3. 逐项证据与修复

- 原目录包含 `PcSecurityCenter.App.pdb`、`PcSecurityCenter.Core.pdb`、`PcSecurityCenter.Data.pdb`、`PcSecurityCenter.Platform.pdb`。`publish.ps1` 的正式发布调用已增加 `-p:DebugSymbols=false -p:DebugType=None`。使用相同参数在新目录构建，递归检查没有 `.pdb`。安装脚本原有 `Excludes: "*.pdb"` 继续保留。
- 运行时库 `clretwrc.dll`、`clrgc.dll` 等仍带微软 CI 的 CodeView 路径；这是上游二进制元数据，没有修改、重签或剥离第三方库。
- `SQLitePCLRaw.batteries_v2.dll`、`SQLitePCLRaw.core.dll`、`SQLitePCLRaw.provider.e_sqlite3.dll` 命中的 `/Users/eric` 来自依赖作者。`System.ComponentModel.TypeConverter.dll`、`System.Private.CoreLib.dll` 命中的 licenseKey 不表明本工具有付费授权逻辑。
- 更新器 `VerifyDownloadedPackageAsync` 在有签名时验证签名；无签名时允许发布清单/校验文件中的 SHA256 验证通过。SHA256 提供完整性比对，不是独立发布者认证。发布说明继续披露未签名状态。
- 发布脚本不再按进程名强制终止用户正在运行的程序。构建目录清理验证绝对路径在 `publish` 内并拒绝重解析点；文件锁冲突会返回错误。
- 对本次源码、测试、工具、文档和工作流进行常见 GitHub token、AWS key、私钥头部模式检查，没有命中。模式检查不是所有凭证类型的完备证明。

## 4. 客户端无法解决的问题

本项目没有付费授权或服务端授权接口，不需要为了保护公开规则引擎而增加服务端依赖。公开下发的规则与程序集可以读取，混淆无法让它们成为秘密。

隔离库密钥由用户侧 DPAPI 保护，不应随发行包分发；本次只打包构建输出及安装说明，没有用户数据库、配置或隔离数据。更新源被同一账户控制时，包与校验和同时被替换的风险不能靠额外一次 SHA256 比对解决；需要代码签名或独立受信任密钥验证。

## 5. 修复顺序

- 已完成：移除本项目发布 PDB、保留第三方二进制完整性、发布说明如实披露签名状态。
- 后续 P1：配置受保护的代码签名证书，验证发布者身份并执行老客户端更新安装验收。
- 后续 P2：根据真实发行目录继续复测元数据暴露。当前开源定位下不增加反调试或混淆，避免影响诊断及杀毒软件兼容性。

远端 CI 和最终 Release 的状态以对应 GitHub 工作流及发布页为准，本文记录发布前本地证据。
